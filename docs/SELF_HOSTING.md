# 自己配布と固定拡張ID（`mail…` プレフィックス）

このドキュメントは、Chrome ウェブストアを使わずに拡張を自分で配布し、
拡張 ID を `mail` で始まる固定値にするための手順をまとめる。

## 前提と制約

- 拡張 ID は「公開鍵(DER SPKI)の SHA-256 先頭16バイトを a–p にずらした32文字」で決まる。
- 使える文字は **a b c d e f g h i j k l m n o p** の16種のみ（q〜z は現れない）。
  そのため `kaz` / `kazu` などは作れず、`mail` は作成可能。
- **Chrome ウェブストアに公開すると、この `key` は無視され、ID は Google が再発行する。**
  `mail…` ID を維持するには、ストアを使わず自己配布（.crx を自分で配布）する必要がある。
- そのぶん、一般ユーザーのワンクリックインストールとストア経由の自動更新は使えない。

## 鍵ファイル（このリポジトリには含めない）

vanity 生成で以下を作成した（`.gitignore` 済み・**秘密鍵は絶対にコミット/共有しない**）:

- `mail-key.private.pem` — 秘密鍵。.crx の署名と将来の再署名に使う。安全に保管する
- `mail-key.pub.b64` — 公開鍵(DER SPKI)の base64。`manifest.json` の `key` に入れる値

## 手順

1. `manifest.json` の先頭付近に `"key": "<mail-key.pub.b64 の中身>"` を追加する
   （このリポジトリでは適用済み。ID が `mail…` に固定される）。
2. 開発時の確認: `chrome://extensions` → デベロッパーモード →「パッケージ化されていない
   拡張機能を読み込む」で読み込むと、ID が `mail…` になることを確認できる。
3. 配布用 .crx の作成:
   ```
   # Chrome/Chromium のパック機能でも作れるが、CLI 例:
   google-chrome --pack-extension=./ --pack-extension-key=./mail-key.private.pem
   # → 一つ上の階層に <dir>.crx が生成される
   ```
   `key` を manifest に入れておけば、pack 時に鍵を指定しなくても ID は一致する。
4. 配布: 生成した .crx を自分のサイト等に置き、利用者に手動インストールしてもらう。
   （企業内なら管理ポリシーで `mail…` ID を許可リスト登録して配れる。）

## 商標に関する注意

`mail` は一般語のため商標上の懸念は小さい。一方で拡張名・アイコン・説明文で
Gmail の公式であるかのような表示は避けること（現状の名称・表記はこの点に配慮済み）。

## ストア公開に切り替える場合

`manifest.json` から `key` を削除（またはそのままでも可だが ID は Google 発行値になる）し、
通常どおり zip をアップロードする。その場合 ID は `mail…` ではなくなる。
